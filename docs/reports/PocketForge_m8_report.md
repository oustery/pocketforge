# PocketForge — M8 (полировка и бета), финал дорожной карты

Дата: 2026-11-19 · Репозиторий: [oustery/pocketforge](https://github.com/oustery/pocketforge) (ветка `main`, публичный)
Пайплайн: каждый пуш в `main` → CI (analyze+test+debug-сборка) → Release с подписанным APK автоматически.

## 1. Что сделано

### Политики сети и разрешений ✅ (то, что settings-страница обещала под «M8»)

- **Проверка нативной политики**: `network_security_config.xml` уже закрывает
  требования M8 — cleartext-трафик запрещён (targetSdk 28 по умолчанию), явное
  исключение только для `127.0.0.1`/`localhost` (opencode serve внутри
  устройства). Все внешние вызовы — HTTPS (GitHub Releases, OAuth Device Flow).
- **Аудит разрешений**: манифест снабжён комментариями «кто и зачем» для каждой
  из четырёх `uses-permission` (INTERNET, REQUEST_INSTALL_PACKAGES,
  FOREGROUND_SERVICE, WAKE_LOCK). Лишних разрешений нет: BACKGROUND_LOCATION,
  READ/WRITE_EXTERNAL_STORAGE не используются — файлы workspace живут в
  частном каталоге приложения.
- **Право установки APK в UI**: новый `canRequestInstall` в канале
  `pocketforge/update` (Kotlin: `packageManager.canRequestPackageInstalls()`,
  minSdk 26 — без версионных проверок) + `UpdateService.canRequestInstall()`.
  В настройках появилась строка «Право на установку APK» с статусом; при
  отсутствии права тап открывает системные настройки и обновляет статус.

### Полировка ✅

- **История команд терминала**: логика `historyUp/historyDown` из M7
  подключена к UI — кнопки ↑/↓ рядом с «Выполнить» листают историю
  (каретка в конец строки, ниже последней — пустой ввод).
- Убрана заглушка «Режим полёта» из настроек (она обещала «M8»), заменена
  реальным разделом «Политики сети» + строкой права установки.

### Бета-выпуск ✅

- Версия `0.3.0+3`; appcast указывает на `pocketforge-v0.3.0-arm64.apk`.
- Дистрибуция беты — публичный GitHub Releases (подписанный APK arm64,
  автоматическая публикация при каждом пуше). Все 8 вех M0–M8 закрыты.

## 3. Итог проекта и ограничения

- **Что получилось**: локальный OpenCode-агент на Android в одном APK —
  proot-песочница (Alpine arm64 + opencode serve) с чатом, git-интеграцией,
  терминалом, in-app обновлениями из GitHub Releases с подписанными сборками
  и воспроизводимым CI/CD пайплайном.
- **Ограничения беты**: терминал — разовые команды без PTY/stdin-потока;
  рендер-проверка проводилась юнит-уровнем (эмулятор в песочнице недоступен,
  Android-сборка локально не запускается — контроль рендера остаётся на
  устройстве); targetSdk 28 — осознанное решение для распространения вне Play.
- **Для следующего цикла** (если потребуется): PTY-терминал (socket-pair +
  потоковый вывод), автотесты UI (integration_test на эмуляторе), публикация
  в F-Droid как альтернативный канал.

## 4. Хотфикс 0.3.1 — ошибка запуска «artifacts.json»

Первый запуск песочницы на устройстве падал с ошибкой artifacts.json.

- **Причина**: манифест `artifacts.json` был объявлен как Flutter-ассет (в APK
  он попадает в `assets/flutter_assets/…`), а `RootfsInstaller` читал его
  Android-AssetManager'ом — `ctx.assets.open(...)` смотрит в корень APK
  `assets/`, где файла не было → `FileNotFoundException` при `startSandbox`.
  Dart-тесты и analyze этого не видят: нативные Kotlin-тесты в CI отсутствуют.
- **Фикс манифеста**: `artifacts.json` перенесён в `android/app/src/main/assets/`
  (Gradle кладёт его в корень `assets/` APK); из pubspec убраны мёртвые
  Flutter-asset-записи.
- **Фикс rootfs**: попытка положить tarball рядом с манифестом показала, что
  AGP/Flutter-сборка не пакует `*.tar.gz` из `src/main/assets` в APK (регрессия
  в CI это поймала). Rootfs больше не бандлится: скачивается при первом
  запуске с Alpine CDN по URL из манифеста, sha256 проверяется существующим
  `ArtifactsDownloader` (тот же путь, что у opencode). APK легче на ~4 МБ,
  сборка не зависит от капризов упаковки ассетов.
- **Регрессия**: в release.yml добавлен шаг, который до публикации проверяет
  наличие `assets/artifacts.json` в собранном APK.
- **UX ошибок**: `RootfsInstaller` оборачивает отсутствие манифеста/ассета в
  IOException с явным текстом (где файл должен лежать).
- **Версия 0.3.1+4** — обновление увидят устройства на 0.3.0 (semver-сравнение
  в in-app update не пропускает сборки с той же версией).

## 5. Сжатие APK (0.3.2): 47.6 → 8.8 МБ

Разбор состава релиза показал, что 43.2 МБ из 47.6 занимал **нестрипнутый
`libflutter.so` с отладочными DWARF-символами** (169.8 МБ в распакованном
виде): `doNotStrip += "**/*.so"` в build.gradle.kts отключал стриппинг для
всех библиотек.

| Правка | Эффект (packed) |
| --- | --- |
| `doNotStrip` только для `libproot.so`; AGP стрипает движок и libapp через NDK | libflutter 43.2 → 5.4 МБ, libapp 3.1 → 2.35 МБ |
| R8 (`isMinifyEnabled` + `shrinkResources`, правила по умолчанию) | dex без изменений (~324 КБ): flutter-сборка **уже** применяла R8 по умолчанию (`--no-shrink` существует — значит, shrink включён); явный конфиг закрепляет это, имена классов переименованы (TarExtractor/RootfsInstaller отсутствуют в dex, RuntimeService сохранён как манифестный) |
| `packaging.jniLibs.excludes` для x86_64/armeabi-v7a | убраны чужие ABI плагинов (~50 КБ); `ndk.abiFilters` не сработал — его перекрывает ABI-логика flutter-плагина |
| Шаг «Отчёт о составе APK» в release.yml | крупнейшие записи печатаются в каждом релизе — регрессии размера видны сразу |

**Итог**: `pocketforge-v0.3.2-arm64.apk` — 8.83 МБ (в 5.4 раза меньше),
подпись и содержимое проверяются в CI перед публикацией. Версия поднята до
0.3.2+5, чтобы устройства на 0.3.1 тоже получили обновление.

## 6. Хотфикс 0.3.3 — «залипшие» сообщения об ошибках и устойчивость загрузок

На устройстве главный экран показывал «Ошибка: Загрузка opencode 1.19.6»
(ранее — «ошибка загрузки Alpine») без причины, лог пуст.

- **Причина №1 (UI)**: `setState` в `RuntimeService` писал `phase`/`message`/
  `progress` в отдельные несинхронизированные поля, а 3-секундный poll из Dart
  мог прочитать разорванный снимок (фаза ERROR + старое сообщение шага).
  Dedupe-опрос сравнивал только фазу/health/прогресс/лог — без `message` и
  `lastError`, — поэтому такое «залипшее» состояние не исправлялось никогда:
  настоящий текст ошибки («Ошибка запуска: …») вытеснялся и не возвращался.
- **Фикс №1**: снимок состояния собирается под `stateLock` (атомарные запись
  и чтение), poll в `runtime_controller.dart` сравнивает и message/lastError.
- **Проверка фактов**: оба URL (Alpine CDN, GitHub releases) и оба sha256 в
  манифесте верны (перепроверены скачиванием в песочнице); Alpine на
  устройстве реально скачался (фаза ушла дальше). Исправлен `sizeBytes`
  opencode (был от x64-ассета: 79 891 356 → 78 461 019).
- **Причина №2 (сеть)**: оставшиеся сбои загрузки — обрывы на мобильных
  сетях и edge-случай докачки: если `.part` уже полного размера, сервер
  отвечает 416 и прежний код валил загрузку после 3 попыток.
- **Фикс №2** (`ArtifactsDownloader`): 5 попыток с паузами, таймауты
  30/60 с, готовый `.part` проверяется sha256 до сети (переживает
  перезапуск сервиса), HTTP 416 = «уже скачано», sha256-mismatch не
  ретраится (детерминирован).
- **Прогресс**: фазы загрузки теперь передают процент в UI (обновление при
  смене целого процента, а не на каждый чанк).
- Версия 0.3.3+6.

## 7. Хотфикс 0.3.4 — сеть внутри песочницы («apk add … код 255»)

Скриншоты устройства (0.3.3 уже установлена — диагностика из п. 6 работала):
rootfs и opencode скачались, установка упала на
«apk add завершился с кодом 255 (нет сети?)», панель «Лог песочницы» пуста.

- **Причина (основная)**: `/etc/resolv.conf` песочницы был зашит публичными
  резолверами (8.8.8.8/1.1.1.1). На мобильных сетях операторы часто блокируют
  «чужие» DNS: внутри proot имена не резолвятся и apk не открывает
  репозитории, при этом Android-сторона качается нормально — системный
  резолвер ходит через DNS оператора.
- **Фикс DNS**: `writeResolvConf` вызывается на каждый запуск и пишет
  реальные DNS-серверы устройства (`ConnectivityManager` → `LinkProperties`,
  добавлен `ACCESS_NETWORK_STATE`), затем публичные фолбэки 8.8.8.8 /
  1.1.1.1 / 9.9.9.9 (первые 4 адреса, `timeout:3 attempts:3`).
- **Страховка репозиториев**: если в распакованном minirootfs нет
  `/etc/apk/repositories` — apk не откроет репозитории (кандидат на код 255);
  `ensureRepositories` восстанавливает файл по ветке из URL rootfs (v3.24).
- **Пакеты перепроверены** по официальному APKINDEX (aarch64): git, bash,
  ripgrep, curl, ca-certificates, libstdc++ — все есть в v3.24.
- **Диагностика доедет до устройства**: при неуспехе apk в карточку ошибки
  идёт хвост `apk.log` (600 байт) с реальным выводом apk; панель «Лог
  песочницы» теперь показывает apk.log + serve.log (раньше — только serve.log,
  который пуст до READY: при падении установки лог всегда был «(пусто)»).
- **Bootstrap ×2**: одиночный сбой DNS/обрыв канала больше не валит установку
  (пауза 3 с между попытками, номер попытки виден в сообщении фазы).
- Версия 0.3.4+7. Если apk add упадёт и после этого — карточка покажет
  точный вывод apk, по нему будет видно следующий шаг.

## 8. Хотфикс 0.3.5 — корень «apk add … код 255»: потерянные симлинки rootfs

Скриншоты устройства на 0.3.4: «apk add завершился с кодом 255» **без хвоста
apk.log** (0.3.4 приклеивает хвост только к непустому логу) и пустая панель
лога. Вывод: apk вообще не стартовал — молчаливый exit 255 у proot это
«execve гостевой программы не удался», т.е. `/bin/sh` в rootfs отсутствует.

- **Корень**: в старом `TarExtractor` ветка симлинков глотала `IOException`
  с комментарием «busybox-пути восстановим apk-комплектом» — но apk
  запускается через `/bin/sh`, который сам является симлинком
  (`/bin/sh → /bin/busybox`): круговая зависимость. Если
  `Files.createSymbolicLink` отказывает (какое-то устройство/FS), все 335
  симлинков minirootfs молча терялись → execve ENOENT → proot молча 255.
  Факт: в alpine-minirootfs-3.24.4-aarch64 515 записей, из них 335
  симлинков (306 абсолютных, 0 цели-каталоги кроме `etc/ssl1.1/certs`).
- **Почему 0.3.4 не помог**: битый rootfs был установлен в 0.3.2, маркер
  `.pf-rootfs-version` стоял — `ensureRootfs` считал установку валидной и
  не переустанавливал.
- **TarExtractor переписан**: два прохода (сначала каталоги+файлы, потом
  ссылки — цели гарантированно на диске); симлинк создаётся любой ценой:
  symlink → hardlink → копия цели (busybox-мультиколл и musl одинаково
  работают как hardlink: один inode, лишнего места нет); dir-цель →
  каталог; каждая неудача — в лог, молчаливых пропусков больше нет.
- **verifyRootfs + автопочинка**: критические пути (bin/sh, busybox(x),
  sbin/apk, ld-musl) проверяются при каждом запуске; битый rootfs
  переустанавливается автоматически (маркер больше не считается
  гарантией). Проверка bin/sh — `isSymbolicLink || exists` без резолва:
  абсолютный симлинк «битый» снаружи rootfs по определению.
- **Preflight-самотест**: перед apk выполняется `proot /bin/echo pf-proot-ok`
  с логом — отделяет «не запускается /bin/sh в proot» от «apk не смог
  скачать пакеты»; при пустом apk.log карточка прямо говорит об отказе
  execve внутри proot.
- **Валидация в песочнице**: имитация новой логики на реальном архиве —
  в режиме «symlink запрещён» 333 замены hardlink'ами, verify OK,
  `bin/sh` = hardlink с контентом busybox, ELF aarch64 подтверждён;
  qemu-user в сборочном сандбоксе недоступен — runtime-проверку делает
  echo-самотест на устройстве.
- Версия 0.3.5+8.
